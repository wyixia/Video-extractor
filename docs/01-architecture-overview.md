## 2. 分层架构说明

| 层 | 名称 | 是否大模型 | 运行位置 | 职责 |
|----|------|-----------|----------|------|
| L0 | 预处理层 | 否（纯算法） | 本地 CPU | 切镜头、抽帧、拆音轨，产出云端调用的"输入锚点" |
| L1 | 云端子任务并行层 | 是（云端 API） | 云端 | 4 个解耦子 Skill，独立 System Prompt / 入参 / 出参 |
| L2 | 汇总 & 校验层 | 是（云端 LLM） | 云端 | 合并、对齐、校验、补全总览与 Caption |
| L3 | 输出适配层 | 否（纯代码） | 本地 | 把 L2 结果转成前端表单 JSON |

**硬性约束落地方式：**
- 所有 LLM/VL 推理走云端 API，本地零部署（预处理层用 CPU 算法）。
- 每个子 Skill 完全解耦：`system_prompt` / `input_schema` / `output_schema` 各自独立，可单独开关与调试。
- 音画分离：VL 只看画面，ASR/SED/音乐只看音频；任何 Skill 不得跨模态脑补（画面里没看到的东西不写进画面字段，音频里没听到的不写进声音字段）。
- 不确定内容统一标 `"无法识别"`；空值统一填 `"无"`；禁止空字段。
- 时间区间：不重叠、不越界（落在视频总时长内）、时序跟随播放顺序。

## 3. 子 Skill 清单（职责 / 输入输出 / 依赖 / 触发条件）

### Skill 1 · 音频解析 Skill（ASR 语音转写）
- **职责**：把人声轨道转写成带时间戳的文本，供表单「人声/台词」字段。
- **输入**：`vocals.wav`（Demucs 分离的人声轨）+ 语言提示（默认中文）。
- **输出**：`[{start, end, text, type(画内/画外)}]`，按 shot 时间窗切片。
- **依赖**：预处理层 Demucs 产物。
- **触发**：预处理完成后，与 Skill 2/3/4 并行。

### Skill 2 · 音频事件识别 Skill（SED 环境音效）
- **职责**：识别环境音 / 特殊音效，供表单「环境音/特殊音效」字段。
- **输入**：`no_vocals.wav`（去掉人声后的音轨，避免人声干扰）。
- **输出**：`[{start, end, event, confidence}]`。
- **依赖**：预处理层 Demucs 产物。
- **触发**：与 Skill 1/3/4 并行。
- ⚠️ **待确认**：SED 云端能力形态（见第 6 节 Q1）。

### Skill 3 · 音乐理解 Skill（BGM 曲风/情绪）
- **职责**：识别背景音乐曲风、情绪、起止变化，供表单「音乐」字段。
- **输入**：`no_vocals.wav`（含伴奏，比纯人声轨更适合识别 BGM）。
- **输出**：`{style, emotion, segments:[{start, end, change}]}`。
- **依赖**：预处理层 Demucs 产物。
- **触发**：与 Skill 1/2/4 并行。
- ⚠️ **待确认**：音乐理解云端能力形态（见第 6 节 Q1）。

### Skill 4 · 核心画面 VL 标注 Skill（景别/机位/运镜/内容）
- **职责**：看关键帧，填写表单字段 3/4/5/6（景别、角度机位构图、运镜、内容信息），是核心 Skill。
- **输入**：单个 shot 的 1~N 张关键帧 + 该 shot 时间窗（仅作上下文，不依赖音频）。
- **输出**：`{shot_size, dynamic_size_change, angle_camera_composition, camera_movement, content{subject,action,expression,enter_exit,interaction,transition}}`。
- **依赖**：预处理层抽帧产物。
- **触发**：**逐 shot 循环调用**（你明确要求的循环逻辑），可与 Skill 1/2/3 并行启动。
- 运镜判断依赖多帧：抽帧策略直接影响运镜准确度（见第 6 节 Q5）。

### Skill 5 · 汇总 & 校验 Skill（LLM）
- **职责**：合并 L1 四路结果 → 对齐 Schema → 时序/区间/内容校验 → 补全总览与 Caption → 输出最终 JSON。
- **输入**：L1 四路结构化结果 + shot_manifest。
- **输出**：适配前端表单的完整 JSON（见第 4 节 Schema）。
- **依赖**：必须等 L1 全部完成（任一失败则对应字段标「无法识别」，不阻塞）。
- **触发**：L1 四路全部返回（成功或降级）后启动。

## 4. 数据 Schema 与表单字段校准（已对齐截图）

### 4.0 表单真实字段（来自截图，全部为必填单行文本，非下拉）
| 字段 | 表单标签 | 占位提示（原文） |
|------|----------|------------------|
| 总体信息 | 总体信息 * | 描述视频基调、整体场景布局、时间进度、色调等全局信息。 |
| 镜号 | 镜号 * | 例如：shot 1，按镜头出现顺序编号。 |
| 时间段 | 时间段 * | 格式 `HH:MM:SS,mmm-HH:MM:SS,mmm`，使用视频内相对时间。 |
| 景别 | 景别 * | 例如：远景、全景、中景、近景、特写；描述镜头内景别。 |
| 角度/机位/构图 | 角度/机位/构图 * | 描述拍摄视角、机位、构图及人物/物体在画中的位置。 |
| 运镜 | 运镜 * | 描述推拉摇移、跟焦、变焦、速度、焦点变化等；固定镜头明确填写。 |
| 内容信息 | 内容信息 * | 描述主体外观、动作、表情、出入画与运动方向、互动及情绪。 |
| 环境音/特殊音效 | 环境音/特殊音效 * | 描述环境声/环境音与特殊音效；没有则填"无"。 |
| 音乐 | 音乐 * | 描述音乐风格、情绪及起止变化；没有则填"无"。 |
| 人声/台词 | 人声/台词 * | 描述说话人 S1/S2、画内/画外、语气；保留 `<d>…</d>`、`<sceneRatio>`、`<cutoff>` 标记，没有则填"无"。 |
| 完整 Caption | 完整 Caption（只读自动生成） | 逐行：总体信息：/ 分镜表：/ 镜号：/ 时间段：/ 景别：/ 角度机位构图：… |

> 布局：镜号与时间段并排两列，其余字段整行。分镜条目支持上移/下移/删除，"＋ 新增一条"。
> 截图顶部另有「子任务 ID」「视频播放器」「播放状态行」「info 调试代码块」——这些是后台 UI / 调试信息，**不是标注字段**，不进 Schema；info 区的时间戳疑似镜头边界，仅作测试切分参考。

### 4.1 与原始 brief 的差异（需你确认取舍，见第 6 节）
- **时间段格式**：表单占位为 `HH:MM:SS,mmm-HH:MM:SS,mmm`（毫秒用逗号、无空格、单连字符）。brief 写的是 `HH:MM:SS - HH:MM:SS`。→ 以**表单**为准生成。
- **台词标记**：表单要求保留 `<d>…</d>`、`<sceneRatio>`、`<cutoff>`；brief 写的是 `<d>台词</d>`、`<scenestart>`、cutoff。→ `<scenestart>` 与 `<sceneRatio>` 不一致，**以哪个为准？**
- **说话人标签**：表单要求"描述说话人 S1/S2"；brief 未提。→ 台词是否强制带 `S1/S2` 说话人前缀？
- **景别动态变化**：表单把"镜头内动态变化"直接写进「景别」单行文本（brief 的字段 3 也确认支持）。→ 不再单列 `dynamic_size_change` 字段，并入 `shot_size` 字符串。
- **总体信息**：表单是单行文本，非大段落 → 改为单行字符串。
- **完整 Caption**：表单为只读自动生成文本区，结构是"总体信息：/ 分镜表：/ 镜号：/ 时间段：/ 景别：…" → 确认为「逐镜拼接 + 总体信息」的只读多行文本。

### 4.2 单 shot 记录（key 与表单字段 1:1，便于直接回填）
```json
{
  "shot_number": "shot 1",
  "time_range": "00:00:00,000-00:00:02,250",
  "shot_size": "中景（镜头内由中景缓慢推至近景）",
  "angle_camera_composition": "平视正面机位，人物居中，前景球台后景挡板",
  "camera_movement": "固定镜头",
  "content_info": "两名运动员持拍对攻，表情专注，无入画出画，互相攻防，无转场",
  "env_sound": "乒乓球撞击声、脚步声",
  "music": "无",
  "speech": "画外 S1 <d>下一球注意落点</d>"
}
```
> 字段约束：景别取值 {远景/全景/中景/近景/特写}；运镜取值 {固定镜头/推/拉/摇/移/跟/变焦/甩镜/环绕/焦点变化}，可组合（如"推+跟"）；无则填"无"；不确定填"无法识别"；禁止空字段。

### 4.3 全局产出（同一 JSON 顶层）
```json
{
  "video_meta": {"filename": "...", "duration_sec": 13.46, "total_shots": 7, "subtask_id": "864689235027272"},
  "shots": [ /* 4.2 数组，严格按 time_range 时序排列，区间不重叠不越界 */ ],
  "overview": "总体信息：13秒乒乓球对攻片段，室内球馆，中近景为主……",
  "full_caption": "总体信息：...\n分镜表：\n  shot 1\n    时间段：...\n    景别：...\n    角度/机位/构图：...",
  "raw_subskills": { "asr": [...], "sed": [...], "music": {...}, "vl": [...] }
}
```
> `raw_subskills` 保留各子 Skill 原始输出，便于前端"展开原文 / 人工复核溯源"。`subtask_id` 取自表单顶部「子任务 ID」。

## 5. 错误处理与降级策略

| 故障场景 | 触发条件 | 降级方案 |
|----------|----------|----------|
| API 超时 | 单次调用 > 阈值（默认 30s） | 退避重试 2 次；仍失败 → 该 shot/字段标「无法识别」，标记 `needs_review=true` |
| 图片解析失败 | 某帧损坏/解码失败 | 自动重抽该帧；全部帧失败 → VL 整体标「无法识别」 |
| 音频识别失败 | ASR/SED/音乐返回空或异常 | 标「无法识别」，不阻塞其他路 |
| JSON 输出异常 | 模型返回非 JSON / 不符 Schema | 严格 Prompt 重试 2 次（去掉解释、强制 JSON）；仍失败 → 「无法识别」+ 告警 |
| 时间区间冲突 | 合并后 shot 重叠/越界 | 校验层修正（按 TransNetV2 原始边界回灌），并记录 `interval_fixed=true` |
| 子 Skill 被关闭 | 配置 `enabled:false` | 对应字段统一填「无」或「无法识别」，流水线继续 |

> 通用原则：单点失败不阻断整条流水线；任何降级都显式留痕（`needs_review` / `interval_fixed`），交人工复核。

### 8.2 云端服务商验证结论
经官方文档核实，**方案 A（通用音频多模态大模型按不同 Prompt 承担 SED 与音乐理解）成立，无需自建 PANNs/BEATs**。百炼同时提供：
- VL：`qwen2.5-vl-72b-instruct` / `qwen3-vl-*`
- ASR：`paraformer`（时间戳固定开启）、`qwen3-asr-flash-filetrans`（句/字级时间戳）
- 音频理解：`qwen3.8-omni-flash`（支持声音事件检测 timestamp JSON 输出）、`qwen3-omni-30b-a3b-captioner`（免 prompt 音频描述，覆盖 speech/ambient/music/sfx）
- 汇总 LLM：`qwen-plus` / `qwen-max`
- ⚠️ `qwen-audio-turbo` 仅免费体验、不可付费、不生产，已排除。

### 8.4 接入约束（写进 config）
- **地域/Key**：音频类模型（Qwen-Omni/Audio/Captioner）需**北京地域 API Key**；VL/ASR 同地域。
- **base_url（OpenAI 兼容）**：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`
- **代理**：若环境设了 `HTTP_PROXY`/`HTTPS_PROXY`（本机 127.0.0.1:7897），SDK 自动走代理；代码统一从环境变量读 Key 与 base_url，不硬编码。
- **超时/重试**：单次调用默认 30s 超时，退避重试 2 次；仍失败 → 该字段「无法识别」+ `needs_review=true`。
