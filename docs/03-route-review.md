# 技术路线复盘：效果、成本、以及"运镜为什么要抽帧"

> 基于真实运行数据（`测试.mp4`，13.46s / 1280×544 / 24fps，切出 7 镜），模型为端点上的 `qwen3.8-flash`（画面）+ `qwen3.6-flash`（总览合并）。

## 1. 实测基线

| 项 | 实测值 |
|----|--------|
| 总耗时 | 30~42 秒 / 7 镜（并发 7） |
| 预处理 | 3.7 秒（scene 检测 + 11 张关键帧 + 抽音轨） |
| 单镜画面调用 | 2 帧 ≈ 1.5k token；3 帧 ≈ 1.8k token |
| token 拆解（2 帧） | 图像 484（242/帧）、Prompt 344、输出 740（其中 reasoning 550） |
| 单镜延迟 | flash 8~16 秒；max 84 秒（同为 2~3 帧） |
| 总览合并 | 17 秒（输入裁剪后）；未裁剪时 80 秒 |

结论：**图像 token 很便宜，成本主要花在 reasoning 和输出上。**

## 2. 效果评估（逐字段）

| 字段 | 质量 | 说明 |
|------|------|------|
| 景别 | 可用，边界不稳 | 7 镜里 4 镜稳定；同一镜多次运行会在"中景/全景"之间摆动 |
| 角度/机位/构图 | 好 | 最稳定、信息密度最高，能描述过肩、对角线、前后景层次 |
| 运镜 | 偏弱 | 同素材三轮分别判为"全固定"、"跟镜头/轻微摇/拉移跟"，结论随帧位变化 |
| 内容信息 | 好 | 能读出球衣号码 846、记分牌 2:0、字幕原文"两人对拉弧圈" |
| 环境音/音乐/台词 | 空 | 该端点无音频能力，全部降级为"无法识别" |
| 跨镜一致性 | 偏弱 | 同一选手颜色在"蓝色/蓝绿色"间漂移，球色"黄/橙"不一致 |

## 3. 运镜为什么不能只靠静态帧判断

运镜是**相机在时间上的几何变换**，不是画面内容：

- 推/拉：整幅画面尺度变化（或焦距变化）
- 摇/移：整幅画面横向/纵向平移
- 跟：相机随主体运动，主体在画面中位置基本不变、背景大幅位移
- 固定：背景参照物位置、尺度都不变

这些量需要**帧间的对应关系**才能算出来。给 VL 2~3 张静态图，它只能靠"背景参照物有没有位移"做间接推断，因此存在原理上无法消除的混淆：

| 混淆对 | 静态帧为何分不开 |
|--------|------------------|
| 推 vs 变焦 | 两者都表现为画面变大，透视关系差异在低分辨率帧上看不出 |
| 摇 vs 移 vs 跟 | 都表现为画面平移，区别在于主体与背景的相对位移，需要连续帧测算 |
| 固定 vs 轻微跟 | 主体自身的动作和相机的运动混在一起，2 帧样本不足以分离 |
| 方向反转 | 推→拉这类中途反向，抽 3 帧会直接漏掉 |

实测佐证：同一段素材、同一模型，仅改帧位置（中间+等间隔 → 首/中/尾），运镜结论从"全部固定镜头"变成"shot 3 跟、shot 6 轻微摇、shot 7 拉+移+跟"。这说明输出是**对有限样本的推断**，不是测量。人工核对首尾帧确实能看到背景挡板位移，即"轻微摇"不是幻觉，但幅度、起止、方向无法保证。

## 4. 那"抽帧"这个方案到底对不对

分两层看：

**作为输入形态：对。** 云端 VL 只能吃图像或视频；抽帧是把视频降维成可控成本输入的合理手段，比整段视频直传便宜一个数量级以上。

**作为运镜判断手段：不够。** 它把几何测量问题交给了语言模型去猜。正确分工是：

```
CPU 测运动（免费、可解释） → 得到 dx/dy/scale 曲线 → 规则分类成候选标签
        ↓
VL 只负责选词、写描述、结合画面内容修正（不负责判断有没有运镜）
```

### 推荐的运镜实现（按成本从低到高）

| 级别 | 做法 | 成本 | 精度 |
|------|------|------|------|
| L0（当前） | 首/中/尾 3 帧 → VL 直接判 | 最低 | 粗，会漂移 |
| L1 | 抽 5~8 帧，只问"是否整体位移/缩放"，输出短标签 | 低（+1k token/镜） | 中 |
| **L2（建议）** | **CPU 全局运动估计**：ffmpeg `vidstabdetect` 轨迹 / 特征点匹配（ORB+RANSAC）/ 相位相关，得到每帧 dx、dy、zoom，聚合成镜头级运动曲线，用阈值规则分类 | **≈0（本地 CPU，几百毫秒/镜）** | 高，且可复现 |
| L3 | 整段视频直传 VL | 高（帧数×图像 token） | 视模型，长片会截断 |

L2 的关键优势不只是准：它产出的是一条**可存证的数字曲线**，人工复核时能直接看到"第 3.2 秒到 4.1 秒画面右移 42px"，而不是一句无法验证的描述。对标注平台来说，这个可追溯性比准确率更重要。

## 5. 整条路线的成本结构

按本片外推（每镜约 1.5k token）：

| 片长 | 镜头数（按 1.5s/镜估） | token 量级 |
|------|------------------------|-----------|
| 13s | 7 | ~1 万 |
| 1 分钟 | ~40 | ~6 万 |
| 10 分钟 | ~400 | ~60 万 |
| 1 小时 | ~2400 | ~360 万 |

**成本随镜头数线性增长，长片会很贵。** 真正影响成本的三个杠杆，按性价比排序：

1. **限 reasoning**：单镜 740 输出里 550 是 reasoning。关掉或限制后，成本直接降 40~50%，质量对结构化字段影响很小。
2. **跨镜复用**：同机位连续镜头，背景/构图描述重复度极高。把上一镜的描述作为上下文、只让模型输出"变化部分"，可省一半以上输出 token，同时解决跨镜一致性（颜色漂移问题正是缺少上下文导致的）。
3. **分级调用**：先用 flash 出一版，只把低置信/复杂镜（多人、快速运动）升级到 max。当前全用 max 会让单镜成本 ×10。

## 6. 结论

- **路线方向是对的**：CPU 做切分与校验、云端做理解、代码做对齐，这个分工在低成本目标下是合理的。
- **三处要改**，按优先级：
  1. **运镜改由 CPU 测量**（L2）。这是唯一"原理上错了"的地方，其余都是精度问题。
  2. **限制 reasoning + 跨镜上下文**。同时降成本、提一致性。
  3. **接音频**。当前台词/音效/音乐三字段全空，人工要补三个字段，这是流水线价值损失最大的一环，而 ASR 恰恰是最便宜的云端能力。
- 抽帧本身不是问题，问题是用抽帧去回答一个需要连续帧才能回答的问题。

## 7. 待确认

1. 运镜是否按 L2 改（CPU 测运动 + VL 只写描述）？这会新增一个预处理模块，但不增加云成本。
2. 音频能力：当前端点无 ASR/音频理解。是否换一个支持音频的服务商只用音频三路，或单独申请 DashScope 的 Paraformer？
3. 长片成本策略：是否需要"同机位镜头合并描述"的优化（省 token，但会让部分镜头的构图字段不再独立生成）。

## 8. 补充：运镜测量实测与取舍（第二轮）

按 L2 思路真正动手做了一版 CPU 运动测量（`src/motion.py`），试了四种实现，全部达不到可用精度：

| 方案 | 结果 | 失败原因 |
|------|------|----------|
| 首尾帧二维模板匹配 | shot 7 明显拉镜头被判"固定" | 长基线里主体动作与相机运动混在一起 |
| 密采样（0.2s）+ 二维 MAE | shot 2 累计 +69% 缩放（不可能值） | 单对 ±3% 噪声，19 对相乘放大到 ±60% |
| 加宽缩放搜索（0.70~1.40） | shot 1 九成帧对被判"跳变"剔除 | 动态画面残差普遍 10~12，阈值一刀切不可用 |
| 1D 边缘投影 + 缩放/平移对齐 | 所有帧对都给 s=1.00、dx=0 | ①`FIND_EDGES` 图像四边有伪边缘，单列尖峰主导归一化，任意两帧高度相关（修掉后降到 0.85 仍有偏）；②素材含溶解转场，整镜变化巨大但没有单帧跳变，投影形状变化不显著 |

**根因**：这台机器的 pip 被环境代理拦住，装不上 numpy / opencv，只能用纯 PIL 做数值计算，精度不够。

**顺带发现的真问题**：这段素材里有 **溶解转场**（不是硬切），ffmpeg 的 scene 检测（阈值 0.08 也不会报）抓不到。所以按"1 个 scene 边界 = 1 个镜号"会切出跨多个机位的"假镜头"——shot 1 和 shot 7 都是这种情况。这也是原设计要用 TransNetV2 的原因：它能识别渐变转场。

**取舍**：把 `preprocess.motion.enabled` 默认设为 `false`。宁可让 VL 目测，也不输出一个自信的错误结论。

**改成"给 VL 明确判据"**，效果反而实在。改 prompt 前 7 镜全判"固定镜头"；改后：

| 镜 | 改前 | 改后 | 依据 |
|----|------|------|------|
| 1 | 固定镜头 | 拉（轻微，广告牌文字露出量增加） | 参照物 |
| 3 | 固定镜头 | 摇（向左） | 背景位移 |
| 5 | 固定镜头 | 摇（向左小幅，VÄSKA 广告牌被右边缘裁切） | 参照物 |
| 6 | 固定镜头 | 摇（向左，记分牌整体右移） | 参照物 |
| 7 | 拉 | 移（环绕跟拍，由端线拉远并移至侧面） | 描述了拉远+横移 |

现在的 prompt 要求它对比"球台边线、球网立柱、广告牌文字、观众席结构、记分牌"这些不动参照物的位置与间距，并写出依据。虽然 shot 1 的方向（推/拉）仍存疑、shot 7 主标签判成"移"而不是"拉"，但每条都有可核对的依据，人工复核成本比"固定镜头"四个字低得多。

**要真正做对运镜，需要下面任一条**（本机装不上，线上环境可以）：

1. `pip install numpy opencv-python-headless` → 用 `goodFeaturesToTrack` + `calcOpticalFlowPyrLK` + `estimateAffinePartial2D`，直接得到 scale/rotation/translation，业界标准做法，单镜几十毫秒。
2. `pip install transnetv2-pytorch torch` → 用 TransNetV2 切镜（含渐变转场），再在真镜头上测运动，误差来源就只剩测量本身。

## 10. 音频能力复核（2026-11-03，逐模型实测）

之前"该端点完全没有音频能力"的结论下得太粗。逐模型实测后，真实情况是：**模型名字在 `/models` 清单里，但音频后端没接上**，四种失败方式各不相同。

| 模型 | 纯文本 | 带音频 | 判定 |
|------|--------|--------|------|
| `qwen-audio-3.0-asr-flash` | 400，响应体 `{}` | 400，响应体 `{}` | 网关无后端，连文本都不过 |
| `qwen-audio-3.0-realtime-plus` | 200，53 字节 `{"status_name":"Success"}` | 同样 200 桩响应 | **假成功**，无 `choices`；realtime 走 WebSocket，HTTP 层只回 ack |
| `qwen-audio-3.0-tts-plus` | 500 `InternalError` | 500 | 文→音模型，不做音频理解 |
| `qwen3.8-flash` / `max` | 200 正常 | 400 `An incorrect modal audio was entered` | 语音理解未开放 |
| `qwen3.8-omni-flash` 等 Omni 系 | 404 `model_not_found` | 404 | **不在本套餐内** |

补充：`/audio/transcriptions`、`/audio/translations` 均 404；`/files` 不是 OpenAI Files API；DashScope 原生 `/api/v1/services/audio/asr/*` 也是 404。

**结论**：这个 token-plan 套餐只开放了文本 + 图像/视频生成类模型。音频三路（ASR / SED / 音乐）必须另开服务商，不能靠换传参格式救回来。

> 探测脚本：`tools/probe_audio_matrix.py`。注意必须显式发 `Content-Type: application/json`，否则 urllib 按 form 编码发送，网关解析不到 `model` 会误报 `Model not exist`（第一版脚本就踩了这个坑，得出错误结论）。

## 11. 音频通道实测结论（2026-11-03 晚，全量端点 maas.qianwenaiapi.com）

### 11.1 两个 key 是两个套餐，不是一个服务商

| Key 前缀 | 端点 | 模型数 | 音频 |
|---|---|---|---|
| `sk-sp-` | `token-plan.maas.qianwenaiapi.com` | 裁剪版 | 全部不可用（见第 10 节） |
| `sk-ws-` | `maas.qianwenaiapi.com` | 183 | **可用** |

两者同属一家代理商的两个入口。音频三路要用全量端点。

### 11.2 此前的"假成功"判断是错的

早期用静音音频测试，模型返回五种声音，据此判定"音频没真正进入模型"。这个推理不成立：

- `usage.prompt_tokens_details.audio_tokens = 58`（8.4s 音频）——音频确实被计数、被处理；
- 同一段音频做转写，输出"可以说这是中国第一高手和世界第一高手的较量"，与画面里的真实解说逐字对上；
- 真正的原因是**SED 任务本身在无画面上下文时会过度联想**：1–2 秒的乒乓击球片段，模型听到"啪"声但不知道是什么，就猜成"篮球运球/金属撞击/齿轮转动/肢体打斗"。

判定音频是否真进去，看 `audio_tokens`，不要用"静音是否也返回内容"来反推。

### 11.3 正确的调用格式

```json
{"type": "input_audio", "input_audio": {"data": "data:audio/mp3;base64,<...>"}}
```

`data` 里必须是完整的 data URL；另加 `format` 字段或塞纯 base64 都会被 400 拒掉。`/audio/transcriptions`、`/audio/translations` 仍是 404，音频只能走 `/chat/completions`。

### 11.4 按镜头切音频是错的，必须用大段音频

同一视频（13.46s / 7 镜）对比：

| 输入粒度 | 环境音结果 | 台词 |
|---|---|---|
| 逐镜头切（1–2s） | 篮球运球 / 金属撞击 / 齿轮转动 / 肢体打斗（7 镜里 5 镜错） | 句子被镜头边界切碎，如"他是中国第一高手，和世界。" |
| 整段（13.46s） | 乒乓球击打台面脆响 + 人群欢呼鼓掌（正确） | "丁宁和对手二比零，可以说这是中国第一高手和世界第一高手的较量。两人对拉弧圈，现场观众看得如痴如醉。"（完整） |

原因：声源判断依赖上下文，1–2 秒里只有几声撞击，模型无从判断物体；整段有连续击球 + 观众反应，场景自然成立。

### 11.5 现在的分工

- **大段音频（默认 60s 一块）跑 ASR / SED / Music 各一次**，拿到带绝对时间戳的结果；
- **按时间戳把结果归属到各镜头**；
- 跨镜的台词按重叠时长比例切分到各镜，并在句首/句尾加 `<sceneRatio>` / `<cutoff>`；
- 调用次数从 21 次（7 镜 × 3 路）降到 3 次，反而更快。

### 11.6 已知残留问题

1. **环境音各镜可能完全相同**：球馆底噪这类持续声，整段识别就是一个事件，归属到每镜都是同一句。物理上合理，但字段区分度低。
2. **长静音段偶发幻觉**：如 5 秒拉镜头段落被描述成"低频轰鸣与呼啸风声"。已在 SED prompt 里加了常见误判黑名单，但没有完全消除。
3. **台词切分可能断词**：模型只给整句起止、没有词级时间戳，按字数比例切会出现"界第一高手的较"这类切法。
4. **无法做纯音频的正/负样本验证**：目前只验证过"无 BGM 的体育赛事"，还没有带背景音乐的样片确认 `present:true` 分支。

## 12. 台词定类：歌词 / 对话 / 画外解说

### 12.1 原先的问题

台词字段统一写成 `画外 S1 <d>…</d>`。MC 录屏里的歌词也被标成"画外"，语义是错的：歌词是人声演唱，不是画外解说。而"画外"这个词本身也是凭空断定的——纯音频根本分不出画内画外。

### 12.2 判断依据拆成两路，各自独立

| 证据 | 来源 | 能判什么 | 不能判什么 |
|---|---|---|---|
| 人声形式 `voice` | ASR（纯音频） | speech / singing / unknown | 画内还是画外 |
| 口型 `mouth_state` | VL（纯画面） | none / speaking / singing / unknown | 有没有声音 |

两个字段都强制只描述自己那一路：ASR 不看画面，VL 不看声音（VL 的硬约束第 1 条仍然禁止从画面推断声音，`mouth_state` 只记录口型的视觉形态）。

`voice` 的关键判据写在 prompt 里：**背景有音乐不等于人声在唱**。说话叠在 BGM 上仍是 `speech`，否则任何带配乐的解说都会被误判成歌词。

### 12.3 判定规则

```
voice=singing                 → 歌词（声音有旋律、贴节拍，比口型可靠）
口型含 singing                → 歌词
口型含 speaking               → 对话
口型含 none（且无上两项）      → 画外解说：画面没人张口，声音只能在画外
口型全是 unknown              → 空标签，交给全片多数补齐；都补不出则写"人声"
```

三条实现细节，都是踩过的坑：

1. **按句判定，不按镜判定**。同一句解说会跨多个镜头，逐镜判会让它在 shot 1 标"人声"、shot 3 标"画外解说"，同一句话出现两种标签。现在先给每句定类，镜头再按句取多数。
2. **一句跨多镜时取最明确的证据**。时间上覆盖到的所有镜头里，只要有一个明确无人张口，整句就判画外。不能因为某一镜看不清就整句判不出来。
3. **证据不足返回空串，不写"人声"当结论**。"人声"只是全片都判不出时的兜底词，不是一类判定。

### 12.4 实测

| 素材 | 口型 | 语音形式 | 结果 |
|---|---|---|---|
| 乒乓（13s，赛事解说） | none / unknown 混 | 4 句全 speech | 7 镜全部 `画外解说` |
| MC 录屏（40s，有 BGM 与歌词） | 5 镜 none、1 镜 unknown | 8 句全 singing | 6 镜全部 `歌词` |

MC 这条恰好验证了"音频优先于口型"：画面是游戏场景没人，口型全是 none，只看口型会判成画外解说；靠 `voice=singing` 才定成歌词。

### 12.5 残留

- 有人在画面里说话但口型看不清（远景、背身、遮挡）时，判不出"对话"，会落到"画外解说"。远景下这是可靠度上限，只能靠人复核。
- 多人对话不区分说话人，标签只到"对话"这一层，没有 S1/S2 编号。
